# 📴 راهنمای کامل نصب آفلاین AmoreChat-Tele

این راهنما برای وقتی است که **سرور به اینترنت بین‌الملل (گیت‌هاب، Docker Hub، Let's Encrypt) دسترسی ندارد**؛ مثلاً در زمان قطعی، یا سروری که از اول فقط شبکه داخلی دارد. همه‌چیز از فایل‌هایی نصب می‌شود که قبلاً دانلود کرده‌اید، و ارتباط با گواهی امنیتی **خود سرور** رمزنگاری می‌شود.

> اگر سرور به اینترنت دسترسی دارد، نصب یک‌خطی ساده‌تر است (README). این راهنما برای حالت بدون اینترنت است.

## ۱. آنچه لازم دارید

- یک سرور **Ubuntu 22.04 یا 24.04** (۶۴ بیتی، x86_64)، حداقل ۲ هسته و ۲ گیگ رم (۴ گیگ بهتر)
- دسترسی **SSH** به سرور با کاربر `root` یا کاربری که `sudo` دارد
- یک **دامنه** که به IP سرور اشاره می‌کند (DNS روی سرویس داخلی مثل ابر آروان)، **یا** فقط **IP سرور**
- یک کامپیوتر که **الان** اینترنت دارد تا فایل‌ها را دانلود کنید (بهتر است این کار را قبل از قطعی انجام دهید)
- **برای بخش تلگرام (اختیاری):**
  - `api_id` و `api_hash` از **https://my.telegram.org** (با همان شماره تلگرامی که دارید وارد شوید ← API development tools ← یک اپ بسازید). این کار اینترنت آزاد لازم دارد؛ **قبل از قطعی** انجامش دهید و دو مقدار را نگه دارید.
  - حداقل یک **کانفیگ VPN/پروکسی** که **از خود سرور** قابل دسترسی باشد (WireGuard، VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC، SOCKS5 یا HTTP). تلگرام فقط از این مسیر وصل می‌شود.

## ۳. انتقال فایل‌ها به سرور

**همه فایل‌ها در یک پوشه روی سرور: `/root/amorechat`**

اول روی سرور پوشه را بسازید:
```bash
mkdir -p /root/amorechat
```

### از ویندوز (PowerShell یا CMD)
در پوشه‌ای که فایل‌ها را دانلود کرده‌اید (به جای `185.1.2.3` IP سرور خودتان):

```
scp amorechat-source.tar.gz amorechat-offline-amd64.tar.gz docker-offline-ubuntu-24.04-amd64.tar.gz root@185.1.2.3:/root/amorechat/
```

(فایل `docker-offline-…` فقط اگر Docker روی سرور نصب نیست — مرحله ۴.)
یا با برنامه گرافیکی **WinSCP**: وصل شوید و فایل‌ها را به پوشه `/root/amorechat` بکشید.

### از لینوکس یا مک
```bash
scp amorechat-source.tar.gz amorechat-offline-amd64.tar.gz docker-offline-ubuntu-24.04-amd64.tar.gz root@185.1.2.3:/root/amorechat/
```

بعد وارد سرور شوید:
```bash
ssh root@185.1.2.3
```

## ۴. Docker نصب است یا نه؟

```bash
docker --version && docker compose version
```

- **هر دو نسخه چاپ شد** ← Docker نصب است. فایل `docker-offline-…` لازم نیست؛ برو به مرحله ۵، **حالت ب**.
- **خطا داد (command not found)** ← Docker نصب نیست. فایل Docker مخصوص نسخه اوبونتوی سرور را هم در پوشه `/root/amorechat` بگذارید و برو به مرحله ۵، **حالت الف**. نسخه اوبونتو را این‌طور ببینید:
  ```bash
  grep VERSION_ID /etc/os-release
  ```
  `24.04` ← فایل `docker-offline-ubuntu-24.04-amd64.tar.gz` | `22.04` ← فایل `docker-offline-ubuntu-22.04-amd64.tar.gz`

## ۵. نصب AmoreChat

### حالت الف: Docker نصب نیست (سه فایل)
در پوشه `/root/amorechat` باید این سه فایل باشد:
```
amorechat-source.tar.gz
amorechat-offline-amd64.tar.gz
docker-offline-ubuntu-24.04-amd64.tar.gz     (یا 22.04)
```
بعد:
```bash
cd /root/amorechat
tar xzf amorechat-source.tar.gz --strip-components=1
sudo DOMAIN=chat.example.ir TLS_MODE=internal ALSO_IP=1 bash deploy/install.sh
```
اسکریپت اول **Docker را از فایل نصب می‌کند** (بدون اینترنت)، بعد AmoreChat را.

> 💡 **کلیدهای تلگرام را همین‌جا هم می‌شود داد** تا بعداً `.env` را دستی ویرایش نکنید:
> ```bash
> sudo DOMAIN=chat.example.ir TLS_MODE=internal ALSO_IP=1 TELEGRAM_API_ID=12345678 TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef bash deploy/install.sh
> ```

### حالت ب: Docker نصب است (دو فایل)
در پوشه `/root/amorechat` این دو فایل کافی است:
```
amorechat-source.tar.gz
amorechat-offline-amd64.tar.gz
```
بعد همان دستورها:
```bash
cd /root/amorechat
tar xzf amorechat-source.tar.gz --strip-components=1
sudo DOMAIN=chat.example.ir TLS_MODE=internal ALSO_IP=1 bash deploy/install.sh
```

### دستور نصب برای آدرس شما
به جای `chat.example.ir` دامنه خودتان را بنویسید:

| می‌خواهید | دستور |
|---|---|
| دامنه + SSL خود سرور (آفلاین) + جواب روی آی‌پی | `sudo DOMAIN=chat.example.ir TLS_MODE=internal ALSO_IP=1 bash deploy/install.sh` |
| فقط آی‌پی (SSL خود سرور) | `sudo DOMAIN=185.1.2.3 TLS_MODE=internal bash deploy/install.sh` |
| دامنه + گواهی خریداری‌شده | اول مثل بالا با `internal` نصب کنید، بعد «سؤالات رایج» سؤال ۱ |
| بدون SSL (فقط پیام؛ تماس کار نمی‌کند) | `sudo DOMAIN=185.1.2.3 TLS_MODE=off bash deploy/install.sh` |

اگر `DOMAIN` یا `TLS_MODE` را ننویسید، اسکریپت می‌پرسد.

اسکریپت:
- Docker را اگر نباشد نصب می‌کند (از فایل `docker-offline-…`، یا اگر نبود از مخزن اوبونتو)
- ایمیج‌ها را **از فایل آفلاین** بارگذاری می‌کند (بدون Docker Hub)
- فایل تنظیمات `.env` را می‌سازد (رمز سرور صدا و IP عمومی خودکار)
- برنامه را اجرا می‌کند و دستور `amorechat-update` را برای آپدیت‌های بعدی نصب می‌کند

در پایان **آدرس‌ها**، **کد راه‌اندازی (SETUP CODE)** و آدرس صفحه نصب گواهی را چاپ می‌کند.

> **Docker فایل ندارید ولی سرور به آینه داخلی اوبونتو دسترسی دارد؟** اسکریپت خودش Docker را از مخزن اوبونتو نصب می‌کند. اگر `apt` خطا داد، مخزن را روی آینه داخلی بگذارید و دوباره نصب را بزنید:
> ```bash
> # Ubuntu 24.04
> sudo sed -i 's#http://[a-z.]*archive.ubuntu.com#http://mirror.arvancloud.ir#; s#http://security.ubuntu.com#http://mirror.arvancloud.ir#' /etc/apt/sources.list.d/ubuntu.sources
> # Ubuntu 22.04
> sudo sed -i 's#http://[a-z.]*archive.ubuntu.com#http://mirror.arvancloud.ir#; s#http://security.ubuntu.com#http://mirror.arvancloud.ir#' /etc/apt/sources.list
> sudo apt-get update
> ```

### آدرس‌ها: دامنه، آی‌پی، با SSL یا بدون SSL
همه در فایل `.env` (پوشه برنامه) تنظیم می‌شوند؛ بعد از تغییر `sudo amorechat-update` بزنید:

| تنظیم | معنی |
|---|---|
| `DOMAIN=` | آدرس اصلی: دامنه یا آی‌پی |
| `TLS_MODE=auto` | SSL رایگان Let's Encrypt (نیاز به اینترنت بین‌الملل؛ برای آی‌پی خودکار به `internal` تبدیل می‌شود) |
| `TLS_MODE=internal` | SSL خود سرور؛ کاملاً آفلاین، هر دستگاه یک بار گواهی را نصب می‌کند |
| `TLS_MODE=custom` | گواهی خودتان: `certs/cert.pem` و `certs/key.pem` |
| `TLS_MODE=off` | بدون SSL (http): پیام و فایل کار می‌کند، **تماس و ویس‌چت نه** (مرورگرها میکروفون را فقط روی اتصال امن می‌دهند) |
| `ALSO_IP=1` | علاوه بر دامنه، روی آی‌پی سرور هم جواب بده: `https://آی‌پی` (SSL خود سرور) و `http://آی‌پی`؛ اگر DNS دامنه در قطعی کار نکند، با آی‌پی وارد شوید |
| `ALLOW_HTTP=1` | برنامه روی `http://دامنه` هم باز شود (به‌جای انتقال خودکار به https) |

> **توصیه:** اگر DNS دامنه‌تان خارج از ایران است (مثلاً Cloudflare)، `ALSO_IP=1` بگذارید تا در قطعی با آی‌پی کار کند؛ یا بهتر، DNS را به سرویس داخلی منتقل کنید.

### بررسی
```bash
sudo docker compose ps
```
باید سه سرویس `app`، `caddy` و `livekit` در حالت **running** باشند.

## ۶. باز کردن پورت‌ها

این پورت‌ها باید هم روی سرور و هم در **فایروال پنل شرکت سرور** باز باشند:

| پورت | کاربرد |
|---|---|
| `80/tcp` | صفحه نصب گواهی و دانلود اپ (`/ca` و `/app`) |
| `443/tcp` و `443/udp` | خود سایت |
| `7881/tcp` | تماس وقتی UDP بسته است |
| `7882/udp` | صدا و تصویر تماس و ویس‌چت |
| `3478/udp` | TURN برای کاربران پشت NAT |

اگر `ufw` روشن باشد، اسکریپت نصب این‌ها را خودش باز می‌کند. دستی:
```bash
sudo ufw allow 80,443,7881/tcp && sudo ufw allow 443,7882,3478/udp
```

## ۸. نصب گواهی امنیتی روی دستگاه‌ها

چون سرور گواهی **خودش** را صادر می‌کند، هر دستگاه باید **یک بار** به آن اعتماد کند؛ وگرنه مرورگر هشدار «اتصال امن نیست» می‌دهد و تماس، میکروفون و نصب برنامه کار نمی‌کند.

### قدم اول (همه دستگاه‌ها)
در مرورگر این آدرس را باز کنید (**http** نه https):
```
http://آدرس-سرور/ca
```
روی **«دانلود گواهی»** بزنید. فایل `amorechat-ca.crt` دانلود می‌شود. همین صفحه راهنمای کوتاه هر سیستم و **اثر انگشت** گواهی را هم نشان می‌دهد.

> 🔐 فقط گواهی را از سرور خودتان و در شبکه‌ای که به آن اعتماد دارید نصب کنید. اثر انگشت را با چیزی که مدیر سرور اعلام کرده مقایسه کنید.

### 📱 اندروید
مسیر در گوشی‌ها کمی فرق دارد؛ در تنظیمات عبارت **«گواهی»** یا **certificate** را جستجو کنید.

| گوشی | مسیر |
|---|---|
| **سامسونگ** | تنظیمات ← امنیت و حریم خصوصی (یا بیومتریک و امنیت) ← سایر تنظیمات امنیتی ← **نصب از حافظه دستگاه** ← **گواهی CA** |
| **شیائومی / پوکو / ردمی** | تنظیمات ← رمزها و امنیت ← حریم خصوصی ← رمزگذاری و اعتبارنامه‌ها ← **نصب گواهی** ← **گواهی CA** |
| **پیکسل و اندروید خام** | تنظیمات ← امنیت و حریم خصوصی ← تنظیمات امنیتی بیشتر ← رمزگذاری و اعتبارنامه‌ها ← **نصب گواهی** ← **گواهی CA** |
| **هوآوی / آنر** | تنظیمات ← امنیت ← تنظیمات بیشتر ← رمزگذاری و اعتبارنامه‌ها ← **نصب از حافظه** |

- فایل `amorechat-ca.crt` را از پوشه Download انتخاب کنید.
- پیغام هشدار «شبکه ممکن است نظارت شود» عادی است؛ **«نصب به هر حال»** را بزنید.
- اگر گوشی قفل صفحه نداشته باشد، اول می‌خواهد یک الگو یا رمز بگذارید.
- مرورگر را **کامل ببندید** و دوباره باز کنید.

> ✅ برای **اپ اندروید AmoreChat** این کار لازم نیست (مرحله ۹).

### 🍏 آیفون و آیپد (دو مرحله؛ مرحله دوم را فراموش نکنید!)
1. صفحه `http://آدرس-سرور/ca` را **در Safari** باز کنید و «دانلود گواهی» را بزنید ← پیغام «Profile Downloaded».
2. **Settings ← General ← VPN & Device Management** ← پروفایل AmoreChat ← **Install** (رمز گوشی را می‌خواهد).
3. **Settings ← General ← About ← Certificate Trust Settings** ← کلید کنار گواهی AmoreChat را **روشن** کنید. ← بدون این مرحله کار نمی‌کند.

### 💻 ویندوز
1. روی `amorechat-ca.crt` دوبار کلیک ← **Install Certificate**.
2. **Local Machine** را انتخاب کنید (برای همه کاربران؛ اجازه مدیر می‌خواهد) یا Current User.
3. **Place all certificates in the following store** ← **Browse** ← **Trusted Root Certification Authorities** ← OK ← Next ← Finish.
4. کروم و اج را کامل ببندید و باز کنید.

یا با PowerShell (به عنوان Administrator):
```
Import-Certificate -FilePath "$env:USERPROFILE\Downloads\amorechat-ca.crt" -CertStoreLocation Cert:\LocalMachine\Root
```

### 🦊 فایرفاکس (همه سیستم‌ها)
فایرفاکس مخزن جدا دارد: **Settings ← Privacy & Security ← Certificates ← View Certificates ← Authorities ← Import** ← فایل را انتخاب ← تیک **Trust this CA to identify websites**.

### 🍎 مک
1. فایل را باز کنید تا در **Keychain Access** (بخش System) اضافه شود.
2. روی گواهی AmoreChat دوبار کلیک ← **Trust** ← **When using this certificate: Always Trust** ← پنجره را ببندید و رمز مک را وارد کنید.

### 🐧 لینوکس (اوبونتو / دبیان)
```bash
sudo cp amorechat-ca.crt /usr/local/share/ca-certificates/amorechat.crt
sudo update-ca-certificates
```
(کروم روی لینوکس: Settings ← Privacy and security ← Security ← Manage certificates ← Authorities ← Import)

### بعد از نصب گواهی
آدرس را با **https** باز کنید: `https://آدرس-سرور` — باید قفل 🔒 بدون هشدار ببینید. حالا می‌توانید برنامه را **نصب کنید** (منوی مرورگر ← «افزودن به صفحه اصلی» / Install app).

## ۹. اپ اندروید

برای اپ اندروید **نیازی به نصب گواهی نیست**:

1. در گوشی `http://آدرس-سرور/app` را باز کنید و اپ را دانلود و نصب کنید (یک بار اجازه «نصب از منابع ناشناس» را بدهید).
2. اپ را باز کنید و آدرس سرور را وارد کنید.
3. اپ می‌گوید سرور گواهی داخلی دارد و یک **اثر انگشت** نشان می‌دهد. آن را با اثر انگشت صفحه `http://آدرس-سرور/ca` مقایسه کنید؛ اگر یکی بود **«اعتماد می‌کنم»** را بزنید.
4. در **پروفایل ← اپ اندروید** باید «اتصال اعلان‌ها: متصل» را ببینید.

> اعلان‌ها مستقیم از سرور خودتان می‌آیند، نه از گوگل؛ پس در قطعی هم کار می‌کنند. در گوشی‌های شیائومی، سامسونگ و هوآوی «اجرای خودکار (Autostart)» را روشن و محدودیت باتری را برای اپ بردارید.

## ۱۰. راه‌اندازی تلگرام (Tele)

با Tele هر کاربر **حساب تلگرام شخصی خودش** را داخل برنامه باز می‌کند، بدون اینکه روی گوشی‌اش VPN نصب کند. ترافیک تلگرام فقط از پروکسی‌ای می‌گذرد که مدیر روی سرور گذاشته؛ اگر هیچ پروکسی سالمی نباشد، تلگرام **هرگز مستقیم وصل نمی‌شود** و چت داخلی هم همیشه روی شبکه خود سرور می‌ماند.

> هر چیزی که Tele لازم دارد (TDLib برای ورود به تلگرام و **sing-box** برای تونل) داخل ایمیج هست؛ روی سرور چیزی جدا نصب نمی‌کنید.

### قدم ۱: کلیدهای تلگرام در `.env`
اگر موقع نصب `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را نداده‌اید:
```bash
cd /root/amorechat
sudo nano .env
```
این دو خط را اضافه کنید (مقدارها از my.telegram.org):
```env
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
```
ذخیره (`Ctrl+O`، Enter، `Ctrl+X`) و اعمال:
```bash
sudo docker compose up -d
```

### قدم ۲: افزودن پروکسی
پنل مدیریت ← **Tele / VPN** ← کادر «افزودن». دو راه دارد:

**الف) فرم دستی** (مثل بخش outbound پنل x-ui): نوع را انتخاب کنید (SOCKS5، SOCKS4/4a، HTTP/HTTPS، VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC، WireGuard) و خانه‌ها را پر کنید. برای SOCKS و HTTP یوزر و پسورد **اختیاری** است. اینجا کد کردن کاراکترهای خاص لازم نیست.

**ب) چسباندن کانفیگ / لینک** (زیر همان تب «راهنمای قالب‌ها» با نمونه همه قالب‌ها هست):


- **WireGuard:** کل فایل `.conf` را **همان‌طور که هست** بچسبانید (از `[Interface]` تا آخر `[Peer]`) و «افزودن» بزنید. یک کانفیگ کامل حساب می‌شود؛ `PresharedKey`، `MTU` و چند `[Peer]` هم پشتیبانی می‌شود. چند فایل WireGuard را هم می‌شود پشت سر هم چسباند؛ هر `[Interface]` یک پروکسی جدا می‌شود.
- **SOCKS / HTTP:** `socks5://USER:PASS@IP:PORT` (بدون رمز: `socks5://IP:PORT`)، `socks4://IP:PORT`، `http://USER:PASS@IP:PORT`. قالب فروشنده‌ها هم خودکار مرتب می‌شود: `IP:PORT:USER:PASS` و `socks5://IP:PORT@USER:PASS`. در لینک، کاراکترهای خاص یوزر/پسورد را کد کنید (`@`←`%40`، `:`←`%3A`، `#`←`%23`).
- **لینک‌ها:** هر لینک در **یک خط**: `vless://` (از جمله Reality، ws، grpc)، `vmess://`، `trojan://`، `ss://`، `hy2://`، `tuic://`، `socks5://`، `http://`
- **لینک اشتراک (subscription):** متن base64 آن را بچسبانید؛ همه لینک‌هایش اضافه می‌شوند.
- **JSON sing-box:** یک outbound، یا کل فایل کانفیگ sing-box (outboundهای قابل‌استفاده‌اش برداشته می‌شوند).

نام هر پروکسی خودکار از خود کانفیگ گذاشته می‌شود (مثلاً `#نام` آخر لینک). کانفیگ ناقص یا ناسازگار همان لحظه با پیام خطا رد می‌شود.

> 🔒 کلیدها و رمزهای کانفیگ‌ها فقط روی سرور ذخیره می‌شوند و در پنل یا برای کاربران نمایش داده نمی‌شوند.

### قدم ۳: تست و انتخاب پروکسی
- دکمه **📈 (تست)** کنار هر پروکسی: سرور واقعاً **از طریق همان پروکسی به سرور تلگرام** وصل می‌شود و تأخیر را اندازه می‌گیرد. «سالم» یعنی تلگرام از این مسیر در دسترس است؛ اگر «خراب» شد، دلیلش کنارش نوشته می‌شود (مثلاً `i/o timeout` یعنی سرور پروکسی جواب نمی‌دهد).
- **سیاست مسیریابی:**

| حالت | کار |
|---|---|
| اولویت | اولین پروکسی سالم به ترتیب «اولویت» (عدد کمتر = جلوتر) |
| بهترین تأخیر | سالمی که کمترین تأخیر را داشته؛ فقط وقتی عوض می‌شود که یکی به‌وضوح سریع‌تر باشد |
| تصادفی | یکی از سالم‌ها؛ تا وقتی سالم است همان می‌ماند |
| دستی | همانی که انتخاب می‌کنید |

- تیک **«فعال‌سازی Tele egress»** را بزنید. خط «تونل: در حال اجرا با «…»» نشان می‌دهد کدام پروکسی در حال استفاده است.

> 💡 **پروکسی با دامنه در قطعی:** اگر آدرس پروکسی دامنه است (نه IP)، در همان بخش خانه **«DNS پروکسی‌ها»** را روی یک DNS داخلی بگذارید (از فهرست: شکن، ۴۰۳، الکترو، رادار)؛ وگرنه DNS خارجی سرور در قطعی جواب نمی‌دهد و تست خطای `lookup … deadline exceeded` می‌دهد.

### قدم ۴: تست خودکار (پیشنهادی)
تیک **«تست خودکار همه پروکسی‌ها»** را بزنید و فاصله را به دقیقه بنویسید (مثلاً `10`). هر بار همه پروکسی‌های روشن تست می‌شوند، بعد طبق سیاست بهترین سالم انتخاب می‌شود و **اگر پروکسی فعلی خراب شده باشد، تونل خودش به سالم بعدی می‌رود**. دکمه «تست همه الان» همین کار را همان لحظه انجام می‌دهد.

### قدم ۵: کاربرها
- هر کاربر از منو ← **تلگرام** ← شماره ← کد (از اپ تلگرام یا پیامک) ← اگر دارد رمز دومرحله‌ای.
- با دکمه **+** گفتگوهایی را که می‌خواهد اضافه می‌کند؛ فقط همین‌ها به‌روز می‌شوند (برای کم ماندن مصرف VPN).
- **عکس:** پیش‌فرض همه فقط متن می‌بینند. در **Tele / VPN ← «عکس در تلگرام»** برای هر کاربر جدا تیک «اجازه عکس» را بزنید و سقف حجم هر عکس را تعیین کنید. عکس اول تار نشان داده می‌شود و فقط با زدن روی آن دانلود می‌شود.

### مصرف VPN
- اگر ۱۰ دقیقه کسی از Tele استفاده نکند، اتصال تلگرام بسته می‌شود و مصرف صفر می‌شود (با باز کردن گفتگو خودش وصل می‌شود). برای تغییر زمان در `.env`: `TELE_IDLE_MINUTES=5` و بعد `sudo docker compose up -d`.
- دانلود خودکار رسانه در تلگرام خاموش است؛ مصرف اتصال فعلی بالای فهرست گفتگوها دیده می‌شود.

## ۱۳. سؤالات رایج

> همه دستورها را **داخل پوشه برنامه** بزنید. اگر نمی‌دانید کجاست:
> ```bash
> sudo docker inspect amorechat-app-1 --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}'
> ```
> بعد از هر تغییر در فایل `.env` یا پوشه `certs/` این دستور تغییرات را اعمال می‌کند (بدون عوض شدن نسخه):
> ```bash
> sudo bash deploy/apply-settings.sh
> ```

### ۱. گواهی SSL خریده‌ام (یا از جای دیگری گرفته‌ام). چطور بگذارمش؟
دو فایل لازم است: **fullchain** (گواهی دامنه + گواهی‌های واسط) و **کلید خصوصی** (private key).
```bash
cp /root/fullchain.pem certs/cert.pem
cp /root/privkey.pem   certs/key.pem
sudo sed -i 's/^TLS_MODE=.*/TLS_MODE=custom/' .env
sudo bash deploy/apply-settings.sh
```
- اسم فایل‌های شما مهم نیست (`.crt`، `.key`)؛ مقصد باید دقیقاً `certs/cert.pem` و `certs/key.pem` باشد.
- اگر گواهی و زنجیره جدا هستند (مثلاً `domain.crt` و `ca-bundle.crt`)، یکی‌شان کنید — **اول گواهی دامنه**:
  `cat domain.crt ca-bundle.crt > certs/cert.pem`
- اگر فایل `.pfx` یا `.p12` دارید:
  ```bash
  openssl pkcs12 -in cert.pfx -nokeys -out certs/cert.pem
  openssl pkcs12 -in cert.pfx -nocerts -nodes -out certs/key.pem
  ```
- بررسی (باید `SSL certificate verify ok` و تاریخ انقضای گواهی شما را ببینید):
  ```bash
  curl -sv https://دامنه-شما/healthz --resolve دامنه-شما:443:127.0.0.1 -o /dev/null 2>&1 | grep -E "subject:|issuer:|expire date:|verify"
  ```
- با گواهی معتبر، دستگاه‌ها **دیگر لازم نیست** گواهی را از صفحه `/ca` نصب کنند.

### ۲. گواهی‌ام دارد منقضی می‌شود. چطور تمدیدش کنم؟
گواهی خریداری‌شده خودکار تمدید نمی‌شود: فایل‌های جدید را جای `certs/cert.pem` و `certs/key.pem` بگذارید و `sudo bash deploy/apply-settings.sh`. داشبورد سلامت (پنل مدیریت) ۲۰ روز مانده به انقضا هشدار می‌دهد.
گواهی **Let's Encrypt** و **خود سرور** خودکار تمدید می‌شوند (Let's Encrypt برای تمدید به اینترنت بین‌الملل نیاز دارد).

### ۳. نوع SSL را عوض کنم (مثلاً از «خود سرور» به Let's Encrypt یا برعکس، یا بدون SSL)
در `.env` مقدار `TLS_MODE` را عوض کنید و `sudo bash deploy/apply-settings.sh`:

| مقدار | یعنی | نیاز به اینترنت خارج | تماس و ویس‌چت |
|---|---|---|---|
| `auto` | Let's Encrypt (رایگان، فقط دامنه) | بله (صدور و هر تمدید) | ✅ |
| `internal` | SSL خود سرور؛ هر دستگاه یک بار گواهی را از `/ca` نصب می‌کند | نه | ✅ |
| `custom` | گواهی خودتان (سؤال ۱) | نه | ✅ |
| `off` | بدون SSL (http) | نه | ❌ (مرورگرها میکروفون را فقط روی اتصال امن می‌دهند) |

### ۴. دامنه یا آی‌پی سرور عوض شده
```bash
sudo sed -i 's/^DOMAIN=.*/DOMAIN=chat.new-domain.ir/' .env
sudo sed -i 's/^PUBLIC_IP=.*/PUBLIC_IP=185.1.2.3/' .env     # آی‌پی عمومی جدید (برای تماس)
sudo bash deploy/apply-settings.sh
```
با SSL خود سرور، گواهی آدرس جدید خودکار ساخته می‌شود و **لازم نیست** دستگاه‌ها گواهی را دوباره نصب کنند (CA همان می‌ماند). در اپ اندروید سرور را با آدرس جدید دوباره اضافه کنید.

### ۵. هم با دامنه، هم با آی‌پی، هم بدون SSL وصل شوم
```bash
echo "ALSO_IP=1" | sudo tee -a .env      # https://آی‌پی (SSL خود سرور) و http://آی‌پی
echo "ALLOW_HTTP=1" | sudo tee -a .env   # http://دامنه هم کار کند (به‌جای انتقال به https)
sudo bash deploy/apply-settings.sh
```
در **اپ اندروید** برای اتصال بدون SSL آدرس را **با `http://`** وارد کنید (مثلاً `http://185.1.2.3`)؛ اگر فقط آی‌پی را بنویسید، اپ اول SSL را امتحان می‌کند و در صفحه گواهی، گزینه «بدون SSL وصل شو» را هم نشان می‌دهد.

### ۶. در قطعی اینترنت بین‌الملل سایت/اپ باز نمی‌شود ولی سرور روشن است
تقریباً همیشه **DNS دامنه خارج از ایران است** (مثلاً Cloudflare، حتی با پروکسی خاموش). داشبورد سلامت این را تشخیص می‌دهد و هشدار می‌دهد. راه‌حل‌ها:
- DNS را به سرویس داخلی منتقل کنید (مثلاً DNS ابر آروان، بدون روشن کردن CDN) — بهترین راه.
- یا `ALSO_IP=1` (سؤال ۵) و در قطعی با آی‌پی وصل شوید.

### ۷. رمز مالک (یا هر کاربری) را فراموش کرده‌ام / گوشی ورود دومرحله‌ای گم شده
```bash
sudo docker compose exec app node server/src/reset-password-cli.js نام_کاربری
```
یک رمز جدید چاپ می‌کند و همه دستگاه‌های آن حساب خارج می‌شوند. اگر ورود دومرحله‌ای هم مانع است، آخرش `--no-2fa` بگذارید. نام کاربری مالک را یادتان نیست؟ دستور را بدون نام کاربری بزنید تا نشانش دهد.
(برای کاربران عادی، مدیر از پنل مدیریت ← کاربران هم می‌تواند رمز را عوض کند.)

### ۸. کد راه‌اندازی (SETUP CODE) را گم کردم
```bash
sudo docker compose logs app | grep "SETUP CODE"
```
این کد فقط تا وقتی اولین حساب (مالک) ساخته نشده کار می‌کند.

### ۹. تماس یا ویس‌چت وصل نمی‌شود (پیام‌ها کار می‌کنند)
- اگر بدون SSL (`http`) وصل شده‌اید: تماس فقط با SSL کار می‌کند.
- پورت‌های `7881/tcp`، `7882/udp` و `3478/udp` را در فایروال سرور **و** پنل دیتاسنتر باز کنید.
- `PUBLIC_IP` در `.env` باید آی‌پی **عمومی** سرور باشد (نه `10.x` یا `192.168.x`)؛ بعد `sudo bash deploy/apply-settings.sh`.

### ۱۰. سرور را خاموش/روشن کنم
```bash
sudo docker compose stop      # خاموش (اطلاعات می‌ماند)
sudo docker compose start     # روشن
sudo docker compose restart   # ری‌استارت
```
⚠️ `docker compose down -v` نزنید: گواهی‌های SSL خود سرور پاک می‌شوند و همه دستگاه‌ها باید دوباره گواهی نصب کنند.

### ۱۱. بکاپ بگیرم / به سرور دیگری منتقل کنم
- بکاپ روزانه خودکار در `data/backups/` است؛ بکاپ همین حالا:
  `sudo docker compose exec app node server/src/backup-cli.js`
- **انتقال کامل به سرور جدید:** روی سرور قبلی `sudo docker compose stop`، بعد کل پوشه برنامه را (با `data/`، `.env` و `certs/`) کپی کنید:
  ```bash
  sudo tar czf amorechat-move.tar.gz amorechat
  scp amorechat-move.tar.gz root@سرور-جدید:/root/
  ```
  روی سرور جدید Docker را نصب کنید (مرحله ۴)، `tar xzf amorechat-move.tar.gz`، فایل کامل `amorechat-offline-amd64.tar.gz` همان نسخه را داخل پوشه `amorechat` بگذارید (اگر سرور جدید اینترنت ندارد) و داخل پوشه `sudo bash deploy/install.sh`. تنظیمات `.env` قبلی استفاده می‌شود و سؤالی پرسیده نمی‌شود. اگر آی‌پی عوض شده، سؤال ۴.
  گواهی SSL خود سرور در حجم Docker است؛ برای اینکه دستگاه‌ها لازم نباشد دوباره نصب کنند، آن را هم منتقل کنید:
  ```bash
  # سرور قبلی
  sudo docker run --rm -v amorechat_caddy_data:/d -v "$PWD":/b alpine tar czf /b/caddy-data.tar.gz -C /d .
  # سرور جدید (قبل از install.sh)
  sudo docker volume create amorechat_caddy_data
  sudo docker run --rm -v amorechat_caddy_data:/d -v "$PWD":/b alpine tar xzf /b/caddy-data.tar.gz -C /d
  ```

### ۱۲. آپدیت آفلاین چه فایل‌هایی لازم دارد؟
بخش ۱۱. معمولاً فقط `amorechat-source.tar.gz`، `manifest.json` و `amorechat-app.tar.gz` (حدود ۴ مگابایت)؛ اگر فایلی کم باشد، دستور آپدیت دقیقاً می‌گوید کدام.

### ۱۳. در اپ اندروید سروری خاموش شده و نمی‌توانم سرور دیگری اضافه کنم
روی صفحه «به سرور وصل نشد» دکمه‌های **سرورهای دیگر**، **افزودن سرور دیگر** و **خروج کامل از این سرور** هست. از داخل برنامه هم: پروفایل و تنظیمات ← اپ اندروید ← آیکون سطل زباله کنار سرور.
